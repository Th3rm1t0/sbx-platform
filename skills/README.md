# skills

配布する skills を置く。全体を1つにまとめた一覧ファイルは持たず、**1つの skill が1つのディレクトリで完結する**。skill を足す PR はそのディレクトリだけを触るので、同時に開いた PR 同士が衝突しない。全体の一覧は CI が生成する。

## ディレクトリの中身

```text
skills/
├── internal/t3rm-<名前>/      自作の skill
│   ├── SKILL.md など           中身（直接編集してよい）
│   └── skill.yaml             意図
└── external/<取得元>/<名前>/   外部の skill
    ├── SKILL.md など           上流の写し（手で直さない）
    ├── skill.yaml             意図
    └── skill.lock.yaml        ロック（機械だけが書く）
```

`skill.yaml` と `skill.lock.yaml` は、中身のハッシュの計算から外す。

意図とロックの分け方の基準: 意図には「こちらの希望」を、ロックには「上流の事実」を書く。

## 意図（skill.yaml）

人や Claude が書く。

| 項目 | 対象 | 必須 | 中身 |
|---|---|---|---|
| 入れる kit | すべて | 必須 | `base` か `team` |
| 取得元 | 外部 | 必須 | GitHub の「組織/リポジトリ」と、skill のディレクトリのパス。GitHub 以外は受けつけない |
| 追いかける対象 | 外部 | 任意 | 省略すると上流の既定ブランチ。タグを指定すると、セマンティックバージョンで一番新しいタグ（プレリリースは除く）を追う |
| 派生元 | 外部から派生した自作 | 任意 | 元になった外部 skill の取得元とコミット |

持ち主の項目は持たない。保留の通知はいつもチャンネル全体に送る。

## ロック（skill.lock.yaml）

外部の skill だけが持つ。取り込みスクリプトだけが書き、CI が照合する。

| 項目 | 中身 |
|---|---|
| コミット | 実際に使っている上流のコミット（SHA） |
| 中身のハッシュ | `skill.yaml` と `skill.lock.yaml` を除いた全ファイルから計算した値 |
| ライセンス | 取り込み時に上流から検出した値。検出できなければ保留 |

同期した日時は書かない。中身が変わったときだけロックが変わるので、変化のない PR は出ない。いつ取り込んだかは git の履歴で分かる。

タグを追う設定で、セマンティックバージョンの形のタグが1つもなければ保留にする。

## 名前

- 自作の skill には `t3rm-` を付ける
- 外部の skill は上流の名前のまま使う
- 外部同士で名前が重なったときは、CI が保留にする
