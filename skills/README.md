# skills

配布する skills を置く。全体を1つにまとめた一覧ファイルは持たず、**1つの skill が1つのディレクトリで完結する**。skill を足す PR はそのディレクトリだけを触るので、同時に開いた PR 同士が衝突しない。全体の一覧は CI が生成する。

## ディレクトリの中身

```text
skills/
├── internal/t3rm-<名前>/      自作の skill
│   ├── SKILL.md など           中身（直接編集してよい）
│   └── skill.yaml             意図
└── external/<取得元>/<名前>/   外部の skill
    ├── SKILL.md など           上流の写し（手で直さない）
    ├── skill.yaml             意図
    └── skill.lock.yaml        ロック（機械だけが書く）
```

`skill.yaml` と `skill.lock.yaml` は、中身のハッシュの計算から外す。

## 意図（skill.yaml）

人や Claude が書く。項目はこれから詰める。いま決まっているもの:

- 入れる kit（`base` か `team`）
- 外部のみ: 取得元のリポジトリとパス
- 外部のみ: 追いかける対象。既定は上流の既定ブランチで、skill ごとにタグに変えられる
- 自作のうち外部から派生したもの: 派生元

## ロック（skill.lock.yaml）

外部の skill だけが持つ。取り込みスクリプトだけが書き、CI が照合する。

- 実際に使っているコミット（SHA）
- 中身のハッシュ

## 名前

- 自作の skill には `t3rm-` を付ける
- 外部の skill は上流の名前のまま使う
- 外部同士で名前が重なったときは、CI が保留にする
